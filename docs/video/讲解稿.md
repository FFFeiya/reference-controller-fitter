## 给网站用的简介（可直接粘贴）

**Reference Controller Fitter：从游戏录像里，拟合出可以直接玩的 2D 角色控制器。**

假设你喜欢某款平台跳跃游戏的手感。把几段它的游戏录像交给这个工具，它会按下面的步骤处理：

1. 自动跟踪角色，并扣除镜头的滚动；
2. 推断出玩家什么时候按了左右键、什么时候按了跳跃；
3. 在 A 到 E 五类由简到繁的控制器模型里，为所有片段寻找同一套参数，最后选出能解释全部片段的最简单的那一个。

拟合结果可以在工具里直接用键盘试玩，也可以导出成 Unity C# 脚本或 Godot 4 脚本，直接放进你的项目。

它做的并不是还原原游戏的源代码，而是找一个“行为相似、结构简单、参数可读、能直接运行”的控制器。报告里也会如实写出哪些参数是录像无法确定的。

**实测结果：**
- 合成测试（真实参数已知）：自动恢复的 8 个参数，误差都在 5% 以内。
- 真实录像（SuperTux、Secret Maryo Chronicles）：每段轨迹误差 1.4%–3.3%。
- 导出的 Unity 脚本已在 Unity 2022.3 和 6000.3 中实际运行验证，Godot 脚本已在 Godot 4.7 中实际运行验证，运动与工具里的模型一致。

## 字幕全文（按章节）

**效果预览**
- 左边是开源游戏 SuperTux 的录像，右边的白色方块是工具自动拟合出的控制器：同样的按键时机下，两条跳跃弧线几乎重合。

**它在做什么**（流程图，无字幕）
- 游戏录像 → 跟踪 → 推断按键 → 联合拟合 → 模型选择 → 试玩 / 导出
- 它不是在还原原游戏的源代码，而是找一个“行为相似、结构简单、参数可读、能直接运行”的控制器。

**① 导入录像**
- 第一步：Add clip，选择一段游戏录像。这里用的是 SuperTux 的公开录像（GPL，来自 Wikimedia Commons）。
- 设定片段的起止帧，然后在第一帧用鼠标框出角色。
- 点击 Track：逐帧跟踪角色，同时根据背景估计镜头的移动，把屏幕上的位置换算成游戏世界里的真实运动轨迹。（快进）
- 橙色线就是角色脚底在游戏世界里的运动轨迹，镜头滚动已经被扣除。

**② 自动拟合**
- 可以导入多段片段：起跑、跳跃、落到低处、停下……这里是两位玩家录制的 4 段片段，它们共用同一个控制器。
- 时间轴上是自动推断出的按键：绿色=按住右，蓝色=左，橙色=跳跃。橙点是录像里的轨迹，青线是控制器的轨迹。推断错了可以直接拖动修改。
- 先换成一个通用的初始控制器：跳得太低、节奏也不对，误差约 47%。
- 点击 Fit Controller：工具在 A–E 五类由简到繁的模型中搜索参数，参数在动、误差一路下降。（快进）
- 最后选出能解释全部片段的最简单模型 D，轨迹误差约 2%。报告会如实写出：哪些参数录像确定不了、哪两种机制分不清。
- Try it：直接用键盘试玩拟合出的手感。轻点空格是矮跳，长按是高跳，空中转向比较“重”。
- Export：填入你的角色在引擎里有多高，导出 Unity C# 脚本 + 参数 JSON，或者 Godot 4 脚本。

**③ Unity 实操**
- 在 Unity 6 里新建一个 2D 项目。
- 把导出的 FittedPlatformerController.cs 和 fitted_controller.json 拖进 Assets。打开脚本就能看到：拟合出的参数就写在开头。
- 搭一个简单关卡：地面、两级台阶、浮空平台和一道沟，都是带 BoxCollider2D 的方块。
- 新建 Player：加 BoxCollider2D 和 FittedPlatformerController 组件（会自动带上 Rigidbody2D，运行时切成 Kinematic）。Inspector 里就是拟合出的参数，可以随时调。
- 可选：把 fitted_controller.json 拖到 Fitted Params Json，游戏启动时用它覆盖参数，以后重新拟合只需替换这个文件。
- 点击 Play。
- 运行：←/→（或 A/D）移动，空格跳跃。轻点空格跳上第一级台阶，长按跳上更高的台阶和浮空平台，再越过沟，最后原地矮跳和高跳。

**④ Godot 实操**
- 把导出的 fitted_platformer_controller.gd 放进项目。同样，拟合出的参数就在脚本开头，都是可以在 Inspector 里改的 @export 变量。
- 场景：地面、台阶和平台用 StaticBody2D + CollisionShape2D。
- 玩家是 CharacterBody2D + CollisionShape2D，挂上这个脚本即可。Pixels per Unit 把“角色身高”单位换算成 Godot 的像素。
- 运行（F5）：方向键移动，空格跳跃。和 Unity 是同一串按键输入。
- 同一个控制器、同一串输入，在 Unity 和 Godot 里的运动几乎一模一样：两边移植的是工具里的同一个精确积分器，并且都在引擎里实测验证过。

**小结**
- 合成测试（已知真实参数）：自动恢复的 8 个参数误差都在 5% 以内
- 真实录像 SuperTux / Secret Maryo Chronicles：每段轨迹误差 1.4% – 3.3%
- 导出的 Unity / Godot 脚本在引擎中实测，运动与工具里的模型一致
- 目前范围：2D 横版的跑、停、转身、各种跳跃、下落与空中控制

## 视频是怎么录的（如实说明）

- **工具部分**：真实程序画面，在离屏模式下渲染，没有占用桌面。
  - 跟踪和拟合过程做了快进。
  - 框选角色的动作由脚本模拟。
  - 试玩时的按键由脚本发出，画面右上角的按键指示显示的是当时“按下”的键。
- **Unity / Godot 编辑器部分**：真实编辑器窗口截图（Unity 6.3、Godot 4.7.2）。
  - 编辑器里的操作由脚本执行，效果和手动操作相同：导入文件、创建物体、添加组件、按下 Play。
  - Unity 用的是编辑器脚本，Godot 用的是编辑器插件。
- **游戏运行画面**：在引擎内以固定帧率逐帧渲染。
  - Unity 使用 `Time.captureFramerate`，Godot 使用 Movie Maker 模式。
  - 按键按预先编好的时间表输入，两个引擎使用同一张时间表，所以可以并排对比。
- 演示用的控制器是工具对 SuperTux 录像的拟合结果（模型 D）。其中跳跃削减系数 Jump Cut = 0.02，意思是松开跳跃键时向上的速度几乎直接归零，类似空洞骑士的手感。工具在报告里把这个参数标成了“录像约束不足”。
- 所有生成脚本都在仓库的 `tools/video/` 中，可以重新生成：
  - `record_tool.py`：录制工具部分
  - `record_unity.py` / `record_godot.py`：录制两个引擎
  - `choreo.py`：用工具内的原型规划演示按键时间表
  - `storyboard.py` / `compose.py`：剪辑与字幕
